# Brin Gym: guide for a Claude Code session

## What this is

A workout web app for one person's iPhone, added to the Home Screen from Safari and published on GitHub Pages under `/brin-gym/`. She picks one of four days and one of three variations, and the app walks her through about 30 minutes: one set at a time, timed rests, and a small looping line drawing of each exercise. The person who maintains it changes it by opening Claude Code in this folder and saying what to change.

Two things matter more than anything else:

1. **Switching apps must never interfere.** She leaves the app constantly, mid-set and mid-rest. Every time shown is computed from timestamps, the workout is saved on every change, and reopening the app returns to the same set with the right times.
2. **It must look and feel like a designed product, not a web page.** `docs/quality-bar.md` is the list of checkable rules. Build to it and audit against it.

Some files in this folder are local only and listed in `.gitignore`. If a `BRIEF.md` is among them, it is the full approved spec and it wins over this file.

## Hard constraints

- **Costs nothing.** No paid service, account, font, art or API, now or later.
- **Nothing loads from another site.** No CDN, analytics, remote font or image. Every URL in `app/` is relative, because the site is served under a sub-path.
- **No sign-in, no accounts, no data leaves the phone.** The app remembers exactly two things: the mute setting and a workout in progress.
- **Plain HTML, CSS and JavaScript modules.** No framework, no build step, no runtime dependency. Playwright is the only dependency and is for tests alone.
- **Sound is Web Audio only**, with `navigator.audioSession.type = "ambient"` where it exists. Never add an `<audio>` or `<video>` element or a sound file: a media element takes over the phone's audio session and pauses her music. Never use a video or audio trick to keep the screen awake.
- **The repository is public.** It holds `app/`, `tools/`, `tests/`, `docs/`, `README.md`, `CLAUDE.md`, `package.json`, `package-lock.json`, `.gitignore` and `.gitattributes`, and nothing else. Never stage anything `.gitignore` excludes, never weaken `.gitignore`, and never write a name, an address, an email or a path from this computer into a public file. Commits use the repository's GitHub no-reply identity.
- **Nothing is created, posted or sent in the maintainer's name** beyond pushing to this one repository when asked to publish.

## Never add

The owner said no to each of these. Do not add them, even as a small convenience, and say so if asked for something that amounts to one of them.

- Calendars, history, streaks, statistics, or any marker of what she did last.
- Weight notes or any logging.
- A "what you'll need" equipment strip, form cues, set-up notes or tips.
- Motivational or cheerful copy of any kind.
- A way to replace the drawings with her own photos or video.
- Notifications, accounts, sharing.
- Exercises or equipment outside the approved list: no barbell squats, Bulgarian split squats, leg curls, shrugs, trap bar, lateral raise machine arm, cable lateral raises, biceps, chest or abs work. Lateral raises and deadlifts are done with dumbbells only.

Copy is plain and in sentence case: no exclamation marks, no emoji.

## Where things live

```text
app/                    the site: only this folder is published (to the gh-pages branch)
  index.html            the shell: meta tags, icons, launch-image links
  manifest.webmanifest  standalone display, relative start_url, scope and id
  sw.js                 service worker: keeps every file in offline-files.json; a new version waits
  offline-files.json    generated by tools/app/offline-list.mjs, never edited by hand
  version.json          the one version value; stamped by npm run publish; shown on About
  .nojekyll             tells GitHub Pages to serve the folder as it is; do not remove
  data/workouts.json    ALL workout content: exercises, reps, sets, rest lengths
  art/<exercise-id>/    1.svg, 2.svg and sometimes 3.svg, in playing order; colour-neutral
  art/credits.json      what the About screen credits
  css/tokens.css        every colour, size and duration; no raw value anywhere else
  js/config.js          behaviour settings that are not workout content
  js/logic/             sequence.js (the order of sets and rests), workout.js (state, pure,
                        takes `now`), session.js (state + clock + save), store.js, format.js, cues.js
  js/platform/          sounds.js, wake-lock.js, updates.js
  js/ui/                copy.js (every word that is not workout content), dom.js, routes.js,
                        drawing.js, screens/
tools/app/              serve.mjs, offline-list.mjs, render-icons.mjs, png.mjs, tokens.mjs, site.mjs
tools/content/          check-workouts.mjs, art-map.json, prepare-art.mjs, contact-sheet.mjs
tools/publish.mjs       npm run publish
tests/logic/            node --test
tests/browser/          Playwright: walk, player, layout, navigation, shell, new-version
tests/fixtures/         small stand-in content the tests run on by default
docs/quality-bar.md     the quality bar
docs/decisions.md       decisions and their alternatives
```

Rules that keep it maintainable:

- Workout content lives only in `app/data/workouts.json`. No exercise name, rep count or rest length appears in code.
- Screen wording lives only in `app/js/ui/copy.js`.
- A colour, size or duration is a token in `app/css/tokens.css`; a behaviour setting is a named constant in `app/js/config.js`.
- `app/js/logic/` has no DOM code and runs in Node.
- Timers never count ticks. An interval only decides when to look at the clock.
- The app has no test-only switch: tests swap content at the server (`tools/app/serve.mjs --fixtures`).

## How to check and publish

```text
npm run check               the content check: workouts.json and every drawing
npm test                    logic tests, then browser tests on tests/fixtures
npm run test:browser:real   browser tests on the real content, all twelve workouts
npm run serve               http://localhost:4173/brin-gym/
npm run screens             screenshots of every screen (SCREENS_CONTENT=real for real content)
npm run publish             check, test, stamp the version, regenerate the offline list,
                            commit, push main, push app/ to gh-pages
npm run test:live           the walk and the offline check on the published site
```

- After any change: `npm run check` and `npm test`. After a change to content or drawings, also `npm run test:browser:real`. After a change to how a screen looks: `npm run screens` and look at the screenshots at both sizes against `docs/quality-bar.md`.
- **Publish only when asked to.** `npm run publish` runs all the tests itself and refuses to continue if one fails. It stamps `app/version.json` first and regenerates the offline list second; never reverse that, and never edit `app/offline-files.json` or the `BUILD` line of `app/sw.js` by hand. Then run `npm run test:live`.
- Pass the session's commit attribution through `--note`: `npm run publish -- --note "<what changed>"`.
- Playwright is pinned to the version whose browsers are installed. If a browser is missing: `npx playwright install chromium webkit`.
- A test that fails is a finding. Fix the cause; do not loosen the test.

## Changing things

- **A workout, a rep count, a rest length:** edit `app/data/workouts.json`, then check, test and publish. The twelve workouts were approved word for word; change them only when asked, and only as asked.
- **A drawing:** edit `tools/content/art-map.json` and re-run `tools/content/prepare-art.mjs` with the two source sets cloned outside this project (README, "Changing a drawing"). The drawings are CC BY-SA 4.0: keep `app/art/credits.json`, `app/art/LICENSE.md`, the About screen and the README's credit in step.
- **A colour or size:** `app/css/tokens.css`. The icons are rendered from the tokens: run `npm run icons` after a palette change.
- **A new iPhone screen size:** add a row to `IPHONE_SCREENS` in `tools/app/render-icons.mjs` and run `npm run icons`.

## The quality bar

`docs/quality-bar.md` holds the full list with how each rule is checked. In short:

- **Design:** always dark plum with one rose-gold accent; two bundled typefaces (Bodoni Moda for headings and numerals, Jost for the rest); no gradients, glow, blur, shadows or cards; no emoji; left-aligned with one clear action per screen; lots of empty space; timer digits that never shift; tap targets of at least 44 px; nothing cut off at 375×667; short, calm motion that respects reduced motion.
- **Feels like an app:** no white flash, no text selection or tap highlight, no double-tap zoom, no rubber-banding on fixed screens, nothing under the notch or the home indicator, and reopening returns to where she was.
- **Code:** small modules, no dead code, no duplicate blocks, no magic numbers, no swallowed errors, no console output, tests on the timer and state logic, and no claim that was not checked.
- **iPhone Home Screen web app:** relative manifest, an opaque 180 px touch icon, launch images, safe areas, cache-first service worker, a new version that never interrupts a workout.

What cannot be tested on a computer needs an iPhone: the icon and name, the launch, the chime over her music, the screen staying awake, and returning after switching apps. Say plainly when a change touches one of these and has not been checked on the phone.
